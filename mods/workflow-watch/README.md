# workflow-watch

A mod (a plugin of function hooks) that opens with every session (unless you turn auto-open off) and tracks everything happening live: main-thread turns (`turn:N`), skills fired (`skill:<name>`), spawned subagents (`agent:<description>`), git commits (`commit:<sha>`), and Workflow stages (`plan`, `scout`, `spec`, `build`, `measure`, `refute`, `arbiter`, `fix`, `close`). It draws only the `Tracker` pane beside the chat and writes nothing into the conversation: it adds no band above the prompt, status line entry, toast or log line. `/tracker` (or `/workflow-watch`) opens the pane and prints the same report as text, which is all the mobile app shows.

In VS Code and the desktop app, every part of the pane is a rounded card. A button at the top right switches the cards between a dark and a light theme, whatever the system theme is. Under it sits the header card with the run name, the output token total and one pill per count (green done, amber running or disputed, red failed). When two or more items are present, the timeline card follows, with the last ten items' spans drawn as rounded bars on the session's shared clock. Bars take their item's kind color: orange turns, violet skills, teal subagents, blue commits, pink Workflow stages. The button above the timeline folds it away (`− Timeline`) or opens it again (`+ Timeline · 22:03 elapsed`). The theme and the fold are both saved, so a new session opens the way you left it.

Under the header sits the usage card, drawn from the engine's own figures rather than estimates. It has three meters: how full the context window is, and how much of the 5-hour and 7-day rate limits you have used, each with a tick where an even burn would sit by now, the signed gap to that tick, and the time until the window resets. Under the meters, one line: the session's cost in dollars where the host keeps a ledger (the CLI does), output and input tokens summed over the turns and subagents, the share of input the prompt cache served, and whether the cache is still warm. A figure the engine has not reported reads `unknown` or is left out, never shown as 0. Each finished card's last line now also carries its input tokens and cache share. The cache clock assumes a 5-minute cache; on a one-hour cache, set the **Prompt cache lifetime** row under `/config` to 60.

The pane also sizes itself. While anything runs it shows every card. After 20 seconds with nothing running it folds to one strip with the run name, its counts, and the item that finished last (or the newest one running). `− Minimize` and `+ Expand`, beside the theme button, override that until the session next starts or stops working. `✕ Hide` closes the pane for the rest of the session. Nothing opens it again until you type `/tracker` or start a new session, and closing it with the surface's own close mark or key counts as a Hide too. The `Auto-open` button beside Hide decides whether the pane opens by itself at all. It is the same setting as the **Open the Tracker pane automatically** row under `/config`. On, which is the default, the pane opens when the session starts and again when work resumes after a quiet spell. Off, only `/tracker` opens it, and it opens at full size in both cases. The terminal folds the same way, without the buttons.

Under that, each item gets its own card, newest first, so the latest work sits just below the timeline and older work further down. The pane scrolls by itself in VS Code and ignores a plugin's request to scroll, so this order keeps the live work in view without following the end. The phase name (`Turn N`, `Skill · <name>`, or the Workflow phase) sits above its cards as a pill in the color of the item that opened the phase. A card shows:

- a round avatar in the kind color, lettered T, S, A, C or W;
- the item label, for a turn with a title taken from your prompt (`turn:3 · Fix the login bug`: its first sentence, cut at a word to 60 characters), then the model alias and the id it resolved to, and the effort level;
- a state pill: ▶ running, ✓ done, ! failed, ! disputed (a fix round that left findings for the arbiter) or ✗ no result (a stage that returned nothing, or died before returning, say on a session limit);
- for a turn, your prompt on an orange `›` line, cut to 100 characters. A message you send while Claude works shows there as `(mid-turn) …` and opens no new turn;
- the one-line result: for a turn, the first sentence of Claude's closing text (`(interrupted)` in front when you stopped it), and for a background subagent the text extracted from `SubagentHandback`, which isn't counted as a tool call;
- the details: `Ran for 0:46 · 5 tools · 0.8k out · 42k in · 91% cached`, or `Running for 0:12 · 3 calls · Bash npm test`;
- for a turn that did something, a digest: `edited 3 files · 7 commands · 1 commit · 2 agents · 1 skill`, counting the items that started while the turn ran.

The text view, which is what `/tracker` prints, the terminal pane shows and the mobile app has, carries four oversight sections under the usage lines, each left out when it has nothing to say. NOW is the plan the agent declared through its task-list calls, with `✓` for a step done, `●` for the one under way and `○` for the rest. DECISIONS lists the question the agent left you at the end of a turn (`? waiting` until your next prompt answers it), the questions you answered and what you picked, and the actions the host refused, with the reason. CHANGES shows the last test run beside the one before it, the four files edited most and how often, the last commits and how many commands ran. QUALITY shows the last review report (findings, fixed, skipped, open, with up to three left open), the verdicts subagents handed back, and the skills fired. The agent's private thinking is blank in the log, so the pane shows what it said out loud: its plan, its recap, its question.

Two things you can do from the pane. Under a turn card, `Copy prompt` puts that turn's prompt on your clipboard and the button reads `Copied` until you copy another. When the context window is 80% full and nothing is running, a `Compact now` button appears in its own row above the other buttons, so none of them moves. It asks for a second press (`Press again to compact`) before it runs the same compaction `/compact` does, and it forgets the first press as soon as work starts. There is no Stop button: the plugin API has none for subagents, and Escape already stops the main turn.

A turn card with more to show than its lines hold gets a `+ more` button. Press it and the card grows: the whole prompt (up to 600 characters) and the whole closing text, wrapped, then the last eight tool calls, one per line. `− less` folds it back. The pane remembers which cards you opened for the rest of the session. A running card is outlined in amber, a finished one in gray. The terminal can't draw these cards, so it shows the same items in box glyphs and follows its own theme colors.

It reads Claude Code's files under `~/.claude/projects/<project>/` every two seconds: `<session>.jsonl` for main-thread turns, skills, agent spawns and commits, `<session>/subagents/agent-<id>.{meta.json,jsonl}` for spawned subagents, and `<session>/subagents/workflows/<run>/journal.jsonl` (plus its `agent-<id>` files) for Workflow runs. `[Request interrupted by user]` is the engine's marker, not a prompt, so it ends the turn rather than opening one. A plugin reads at most 4 MiB at a time, and a long session with pasted screenshots goes past that. Past 4 MiB, the log is read through a filter that keeps every line valid JSON. It drops the engine's bookkeeping lines (copies of API requests, titles, bridge state), empties the base64 data of pasted images, and cuts any string past 2,000 characters, so a 10 to 12 MiB log comes to 1 or 2 MiB and parses to the same items. Windows PowerShell runs the filter on Windows, called by its full path, and `perl` everywhere else, including the 5.34 that macOS ships as `/usr/bin/perl`. The patterns and sizes reach it as environment variables, never as part of its script, and so does the log's path for PowerShell (perl gets it as its file argument). A file is filtered again only when its size changes, and a failed run is not retried until then. If a log still can't be read, the pane keeps the items it last found and says so above them. A very long session can still be over 3.5 MiB after filtering; on the logs measured, that took more than 30 MB of log. Then only its newest whole lines are kept and the pane says so. The earliest turns drop out of the cards and the header counts, and turn numbers start again from the oldest turn kept. On Windows inside the VS Code extension host (where `HOME` is unset), it resolves the user directory from `USERPROFILE`. It also parses Antigravity extension transcripts (`~/.gemini/antigravity/brain/<id>/.system_generated/logs/transcript.jsonl` or `transcript_full.jsonl`) and links spawned subagent conversations automatically.

Install with the marketplace (`/plugin install workflow-watch@alonbaron`) or load it for one session with `claude --plugin-dir <this folder>`. Works both in the terminal CLI and inside the VS Code Claude Code and Antigravity extensions. The pane needs a terminal of 144 columns, or `/tracker` (`/workflow-watch`) to seat it narrower. `scripts/tracker.mjs` renders the same session or workflow feed to HTML or PNG from outside a session with auto-reload for VS Code Simple Browser or Live Preview (`--watch`).

Check it: `claude plugin validate mods/workflow-watch`, `claude plugin test mods/workflow-watch`, `tsc -p mods/workflow-watch` once a session has laid the types beside it. `node mods/workflow-watch/tests/slim-check.mjs [--perl <path>] [log.jsonl ...]` (Node 24) runs the real filter through this machine's PowerShell or perl on generated logs (one under the 3.5 MiB tail, one far past it, one with a 90,000-escape string and an unfinished last line) and on any logs you name. The `tracker-slim` CI job runs it on macOS (every perl in `/usr/bin`), Ubuntu and Windows.
