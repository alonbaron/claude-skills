# workflow-watch

A mod (a plugin of function hooks) that opens with every session and tracks everything happening live: main-thread turns (`turn:N`), skills fired (`skill:<name>`), spawned subagents (`agent:<description>`), git commits (`commit:<sha>`), and Workflow stages (`plan`, `scout`, `spec`, `build`, `measure`, `refute`, `arbiter`, `fix`, `close`). It draws only the `Tracker` pane beside the chat and writes nothing into the conversation: it adds no band above the prompt, status line entry, toast or log line. `/tracker` (or `/workflow-watch`) opens the pane and prints the same report as text, which is all the mobile app shows.

In VS Code and the desktop app, every part of the pane is a rounded card. A button at the top right switches the cards between a dark and a light theme, whatever the system theme is. Under it sits the header card with the run name, the output token total and one pill per count (green done, amber running or disputed, red failed). When two or more items are present, the timeline card follows, with the last ten items' spans drawn as rounded bars on the session's shared clock. Bars take their item's kind color: orange turns, violet skills, teal subagents, blue commits, pink Workflow stages. The button above the timeline folds it away (`− Timeline`) or opens it again (`+ Timeline · 22:03 elapsed`). The theme and the fold are both saved, so a new session opens the way you left it.

Under that, each item gets its own card, newest first, so the latest work sits just below the timeline and older work further down. The pane scrolls by itself in VS Code and ignores a plugin's request to scroll, so this order keeps the live work in view without following the end. The phase name (`Turn N`, `Skill · <name>`, or the Workflow phase) sits above its cards as a pill in the color of the item that opened the phase. A card shows:

- a round avatar in the kind color, lettered T, S, A, C or W;
- the item label, the model alias and the id it resolved to, and the effort level;
- a state pill: ▶ running, ✓ done, ! failed, ! disputed (a fix round that left findings for the arbiter) or ✗ no result (a stage that returned nothing, or died before returning, say on a session limit);
- for a turn, your prompt on an orange `›` line. A message you send while Claude works shows there as `(mid-turn) …` and opens no new turn;
- the one-line result: Claude's latest words for a turn (`(interrupted)` in front when you stopped it), and for a background subagent the text extracted from `SubagentHandback`, which isn't counted as a tool call;
- the details: `Ran for 0:46 · 5 tools · 0.8k tokens`, or `Running for 0:12 · 3 calls · Bash npm test`.

A running card is outlined in amber, a finished one in gray. The terminal can't draw these cards, so it shows the same items in box glyphs and follows its own theme colors.

It reads Claude Code's files under `~/.claude/projects/<project>/` every two seconds: `<session>.jsonl` for main-thread turns, skills, agent spawns and commits, `<session>/subagents/agent-<id>.{meta.json,jsonl}` for spawned subagents, and `<session>/subagents/workflows/<run>/journal.jsonl` (plus its `agent-<id>` files) for Workflow runs. `[Request interrupted by user]` is the engine's marker, not a prompt, so it ends the turn rather than opening one. A plugin reads at most 4 MiB at a time, and a long session with pasted screenshots goes past that. Past 4 MiB, the log is read through a filter that keeps every line valid JSON. It drops the engine's bookkeeping lines (copies of API requests, titles, bridge state), empties the base64 data of pasted images, and cuts any string past 2,000 characters, so a 10 to 12 MiB log comes to 1 or 2 MiB and parses to the same items. A very long session can still be over 3.5 MiB after that (on the logs measured, that took more than 30 MB of log). Then only its newest whole lines are kept, so the pane shows the latest work, and the earliest turns drop out of the cards and the header counts. Windows PowerShell runs it on Windows, called by its full path, and `perl` everywhere else. The log's path and the patterns reach it as environment variables, never as part of its script. A file is filtered again only when its size changes, and a failed run is not retried until then. If a log still can't be read, the pane keeps the items it last found and says so above them. On Windows inside the VS Code extension host (where `HOME` is unset), it resolves the user directory from `USERPROFILE`. It also parses Antigravity extension transcripts (`~/.gemini/antigravity/brain/<id>/.system_generated/logs/transcript.jsonl` or `transcript_full.jsonl`) and links spawned subagent conversations automatically.

Install with the marketplace (`/plugin install workflow-watch@alonbaron`) or load it for one session with `claude --plugin-dir <this folder>`. Works both in the terminal CLI and inside the VS Code Claude Code and Antigravity extensions. The pane needs a terminal of 144 columns, or `/tracker` (`/workflow-watch`) to seat it narrower. `scripts/tracker.mjs` renders the same session or workflow feed to HTML or PNG from outside a session with auto-reload for VS Code Simple Browser or Live Preview (`--watch`).

Check it: `claude plugin validate mods/workflow-watch`, `claude plugin test mods/workflow-watch`, `tsc -p mods/workflow-watch` once a session has laid the types beside it. `node mods/workflow-watch/tests/slim-check.mjs [--perl <path>] [log.jsonl ...]` (Node 24) runs the real filter through this machine's PowerShell or perl on generated logs past the limit, and on any logs you name. The `tracker-slim` CI job runs it on macOS (every perl in `/usr/bin`), Ubuntu and Windows.
