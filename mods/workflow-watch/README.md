# workflow-watch

A mod (a plugin of function hooks) that opens with every session (unless you turn auto-open off) and tracks everything happening live: main-thread turns (`turn:N`), skills fired (`skill:<name>`), spawned subagents (`agent:<description>`), git commits (`commit:<sha>`), and Workflow stages (`plan`, `scout`, `spec`, `build`, `measure`, `refute`, `arbiter`, `fix`, `close`). It draws only the `Tracker` pane beside the chat and writes nothing into the conversation: it adds no band above the prompt, status line entry, toast or log line. `/tracker` (or `/workflow-watch`) opens the pane and prints the same report as text, which is all the mobile app shows.

In VS Code and the desktop app the pane is a console: one monospace grid, hairline rules with their section names inset, one accent color for what is alive or good, amber and red only for trouble. A button at the top right switches it between a dark slate and a warm paper theme, whatever the system theme is, and the choice is saved. The sections run in the order you need them while work runs. SESSION is one rule with the run name, the counts and the clock. NOW is the live turn (or the last one): its title, how long it has run, its tools and tokens, what it is doing right now, and under that the plan the agent declared with `✓` for a step done, `●` for the one under way and `○` for the rest. DECISIONS, CHANGES and QUALITY follow when they have something to say; what they hold is described under the text view below, since the panels draw the same lines. Then USAGE, then TURNS.

USAGE is drawn from the engine's own figures rather than estimates. It has three meters of twenty cells each: how full the context window is, and how much of the 5-hour and 7-day rate limits you have used, each with a notch where an even burn would sit by now, the signed gap to that notch, and the time until the window resets. Under the meters, one line: the session's cost in dollars where the host keeps a ledger (the CLI does), output and input tokens summed over the turns and subagents, the share of input the prompt cache served, and whether the cache is still warm. A figure the engine has not reported reads `unknown` or is left out, never shown as 0. Each finished card's last line now also carries its input tokens and cache share. The cache clock assumes a 5-minute cache; on a one-hour cache, set the **Prompt cache lifetime** row under `/config` to 60.

The pane also sizes itself. While anything runs it shows every section. After 20 seconds with nothing running it folds to NOW alone, plus DECISIONS if a question is waiting for you. `− Minimize` and `+ Expand`, beside the theme button, override that until the session next starts or stops working. `✕ Hide` closes the pane for the rest of the session. Nothing opens it again until you type `/tracker` or start a new session, and closing it with the surface's own close mark or key counts as a Hide too. The `Auto-open` button beside Hide decides whether the pane opens by itself at all. It is the same setting as the **Open the Tracker pane automatically** row under `/config`. Where the engine refuses a plugin's write to that row, as it does in a relayed session such as the desktop app's, the button keeps the choice in the mod's own store, and that choice wins over the row from the next session on. On, which is the default, the pane opens when the session starts and again when work resumes after a quiet spell. Off, only `/tracker` opens it, and it opens at full size in both cases. The terminal folds the same way, without the buttons.

TURNS lists one entry per turn, newest first, so the latest work sits just under the rule and older work further down. The pane scrolls by itself in VS Code and ignores a plugin's request to scroll, so this order keeps the live work in view without following the end. An entry shows:

- a head row: the turn number, its state as a glyph and a word (`✓ DONE`, `● LIVE`, `× FAILED`, `× NO RESULT`), how long it ran, and at the right its tool count and output tokens, with the cache share once it is done;
- a title taken from your prompt (its first sentence, cut at a word to 60 characters) in bold;
- your prompt on a `›` line, cut to 100 characters. A message you send while Claude works shows there as `(mid-turn) …` and opens no new turn;
- while the turn runs, the tool it is in (`▸ Bash npm test`); once it is done, the first sentence of Claude's closing text (`(interrupted)` in front when you stopped it);
- for a turn that did something, a digest: `edited 3 files · 7 commands · 1 commit · 2 agents · 1 skill`, counting the items that started while the turn ran;
- under that, on a thin tree, the skills, subagents and commits that started inside the turn: `skill ponytail`, `agent review correctness ● 1:12 · 2.1k out`, `commit a5927d0 subject`. A subagent's row shows what it handed back once it is done. Workflow stages, and any item that started outside every turn, are entries of their own.

The text view, which is what `/tracker` prints, the terminal pane shows and the mobile app has, carries four oversight sections under the usage lines, each left out when it has nothing to say. NOW is the plan the agent declared through its task-list calls, with `✓` for a step done, `●` for the one under way and `○` for the rest. DECISIONS lists the question the agent left you at the end of a turn (`? waiting` until your next prompt answers it), the questions you answered and what you picked, and the actions the host refused, with the reason. CHANGES shows the last test run beside the one before it, the four files edited most and how often, the last commits and how many commands ran. QUALITY shows the last review report (findings, fixed, skipped, open, with up to three left open), the verdicts subagents handed back, and the skills fired. The agent's private thinking is blank in the log, so the pane shows what it said out loud: its plan, its recap, its question.

Two things you can do from the pane. Under a turn card, `Copy prompt` puts that turn's prompt on your clipboard and the button reads `Copied` until you copy another. When the context window is 80% full and nothing is running, a `Compact now` button appears in its own row above the other buttons, so none of them moves. It asks for a second press (`Press again to compact`) before it runs the same compaction `/compact` does, and it forgets the first press as soon as work starts. There is no Stop button: the plugin API has none for subagents, and Escape already stops the main turn.

A turn entry with more to show than its lines hold gets a `+ more` button. Press it and the entry grows: the whole prompt (up to 600 characters) and the whole closing text, wrapped, then the last eight tool calls, one per line. `− less` folds it back. The pane remembers which entries you opened for the rest of the session. The terminal can't draw the panels, so it shows the same lines in box glyphs, keeps its text timeline, and follows its own theme colors.

Every section after NOW has a fold button above it. `− Changes` folds the section down to the button alone, which then reads `+ Changes · 4`, the number being what you are no longer seeing: lines for DECISIONS, CHANGES and QUALITY, meters for USAGE, entries for TURNS. Press it again to open the section. The set you folded is saved with the theme, so a pane you trimmed to NOW and TURNS stays that way in your next session. SESSION and NOW have no fold. TURNS itself shows the last eight entries, and its rule reads `LAST 8 OF 23` so you know how much lies behind it. `Show all 23`, beside the fold button, lists every entry and `Last 8` cuts the list back; each session starts on the last eight.

It reads Claude Code's files under `~/.claude/projects/<project>/` every two seconds: `<session>.jsonl` for main-thread turns, skills, agent spawns and commits, `<session>/subagents/agent-<id>.{meta.json,jsonl}` for spawned subagents, and `<session>/subagents/workflows/<run>/journal.jsonl` (plus its `agent-<id>` files) for Workflow runs. `[Request interrupted by user]` is the engine's marker, not a prompt, so it ends the turn rather than opening one. A plugin reads at most 4 MiB at a time, and a long session with pasted screenshots goes past that. Past 4 MiB, the log is read through a filter that keeps every line valid JSON. It drops the engine's bookkeeping lines (copies of API requests, titles, bridge state), empties the base64 data of pasted images, and cuts any string past 2,000 characters, so a 10 to 12 MiB log comes to 1 or 2 MiB and parses to the same items. Windows PowerShell runs the filter on Windows, called by its full path, and `perl` everywhere else, including the 5.34 that macOS ships as `/usr/bin/perl`. The patterns and sizes reach it as environment variables, never as part of its script, and so does the log's path for PowerShell (perl gets it as its file argument). A file is filtered again only when its size changes, and a failed run is not retried until then. If a log still can't be read, the pane keeps the items it last found and says so above them. A very long session can still be over 3.5 MiB after filtering; on the logs measured, that took more than 30 MB of log. Then only its newest whole lines are kept and the pane says so. The earliest turns drop out of the cards and the header counts, and turn numbers start again from the oldest turn kept. On Windows inside the VS Code extension host (where `HOME` is unset), it resolves the user directory from `USERPROFILE`. It also parses Antigravity extension transcripts (`~/.gemini/antigravity/brain/<id>/.system_generated/logs/transcript.jsonl` or `transcript_full.jsonl`) and links spawned subagent conversations automatically.

Install with the marketplace (`/plugin install workflow-watch@alonbaron`) or load it for one session with `claude --plugin-dir <this folder>`. Works both in the terminal CLI and inside the VS Code Claude Code and Antigravity extensions. The pane needs a terminal of 144 columns, or `/tracker` (`/workflow-watch`) to seat it narrower. `scripts/tracker.mjs` renders the same session or workflow feed to HTML or PNG from outside a session with auto-reload for VS Code Simple Browser or Live Preview (`--watch`).

Check it: `claude plugin validate mods/workflow-watch`, `claude plugin test mods/workflow-watch`, `tsc -p mods/workflow-watch` (its `tsconfig.json` includes `.claude-plugin/types`, which a session lays beside the mod once it has loaded it). `node mods/workflow-watch/tests/slim-check.mjs [--perl <path>] [log.jsonl ...]` (Node 24) runs the real filter through this machine's PowerShell or perl on generated logs (one under the 3.5 MiB tail, one far past it, one with a 90,000-escape string and an unfinished last line) and on any logs you name. The `tracker-slim` CI job runs it on macOS (every perl in `/usr/bin`), Ubuntu and Windows.
